# Nodara — auditoria funcional de 12 setembro 2026

## Conclusão

O portal e os seis motores têm uma base funcional testável, mas a biblioteca continua alpha. As 100 receitas não equivalem a 100 componentes independentes nem a 69 implementações geométricas completas. O catálogo agora apresenta 69 configurações e explicita presets partilhados e limitações.

## Validação executada

| Verificação | Resultado | Alcance |
| --- | --- | --- |
| Biblioteca, adaptadores, regressões e gerador | 402 testes aprovados | Vitest/Happy DOM; canvas instrumentado para coordenadas e primitivas |
| HTML de produção | 3 aprovados | Portal, catálogo, documentação; Worker compilado |
| Browser ponta a ponta | 64 aprovados; 4 omitidos por formato | Chromium desktop e emulação Pixel 7 |
| Catálogo completo | 100/100 em cada formato | Cliques reais, opções ativas, dados não vazios e pixels desenhados; ausência de pageerror |
| Geração de integrações | 500 combinações analisadas | 100 receitas × React, Vue, Angular, JS e Web Components |
| React gerado | 100 componentes tipados | TypeScript contra os pacotes compilados, não aliases para src |
| Angular gerado | 100 templates AOT compilados | strictTemplates e metadados do pacote distribuível |
| Downloads | 5 pacotes instalados num consumidor limpo | Exports dos seis motores, CSS e metadados Angular verificados |
| Verificações estáticas | lint, typecheck e build aprovados | Inclui agora o TypeScript do portal |
| Auditoria npm sem devDependencies | 0 vulnerabilidades reportadas | Não equivale a uma auditoria de segurança completa |

Os testes de montagem/pixels detetam falhas de execução e ausência de desenho; não provam correção matemática de todos os algoritmos. Não foram executados Firefox, Safari/WebKit, leitores de ecrã reais, dispositivos móveis físicos ou uma certificação WCAG. Os testes Angular de templates são reais; os testes de lifecycle existentes continuam a instanciar as classes diretamente.

## Implementado nesta revisão

- Segmento de integração com cinco stacks, ficheiros completos, imports, CSS, dados validados, eventos, instalação por downloads e instruções por framework.
- Código gerado a partir dos mesmos dados/opções efetivos do preview. Alterações inválidas conservam a última visualização e o último código válidos.
- JSON com atualização automática e modo manual; altura e interatividade controláveis. Cópia com confirmação e recuperação quando o browser bloqueia clipboard.
- Serialização segura de texto contendo `</script>` nos exemplos Vue/HTML.
- Contraste dos rótulos de famílias no modo claro, tipografia do editor/código e layout dos controlos em ecrãs estreitos.
- Escalas X numéricas/temporais proporcionais; domínio Y sem spread que rebentava em 100 mil pontos; limites estatísticos incluídos no domínio; eixos independentes da grelha.
- WebGL limitado a scatter no Chart para não transformar linhas, áreas e barras em nuvens de pontos.
- Calendários respeitam interatividade; editar uma ocorrência destaca essa ocorrência sem apagar a série. `excludedOccurrences` e `replaceCalendarEvent` preservam a sequência.
- Recorrências antigas reaparecem na janela atual; validação de opções RRULE; datas mensais inexistentes são saltadas sem deriva para outro dia.
- Meses anuais com o número real de dias; reservas de timeline sem reciclar três linhas sobrepostas; arrastar no mês usa sete colunas, não 42.
- Níveis hierárquicos DAG propagados em ordem topológica.
- Latitude do centro geográfico aplicada nas projeções planas; rotas respeitam o modo; valores negativos não geram raios NaN.
- Ações acessíveis desativadas deixam de emitir eventos em Chart, Topology, GeoMap e Diagram.
- Vue e Angular encaminham os eventos de alteração/viewport em falta. Todos os adaptadores limpam opções removidas ao mudar de receita.
- Angular distribuído com compilação parcial, em vez de um bundle sem metadados de componente. Compatibilidade declarada: Angular 21.2.21–21.x.

## Limites que continuam por resolver

| Área | Estado real |
| --- | --- |
| Sankey / Alluvial | Partilham motor; Alluvial não possui estratos temporais próprios |
| Tree / Org chart; Radial tree / Mindmap | Presets de layouts partilhados |
| Flowchart / ER / State | Caixas e ligações; sem notação ER especializada ou máquina de estados |
| Treemap / Icicle / Sunburst / Circle-pack | Implementações base; contenção/packing hierárquico completo por fazer |
| Contour / Violin | Ilustrações de densidade; não são isolinhas/KDE científicos validados |
| Histogram | Recebe bins agregados; não faz binning de amostras brutas |
| Caminho crítico | Preset de dependências; não calcula CPM/folgas |
| Schedulers especializados | Vistas timeline/resource/agenda são de consulta/seleção; a edição está nas grelhas dia/semana/mês |
| Fusos e recorrências | RRULE parcial; fuso formata rótulos, grelha segue o browser; não é implementação integral RFC 5545 |
| Mapas | Sem cartografia mundial, tiles ou geocoding incluídos; polígonos fornecidos pelo integrador |
| Grandes volumes | Regressão de domínio com 100k pontos, não um SLA de renderização de todos os tipos |
| Distribuição | Downloads alpha instaláveis; @nodara/core e @nodara/react retornaram 404 no npm público |
| Dependências de desenvolvimento | Auditoria completa reporta 22 avisos (12 altos, 10 moderados); exigem atualização/validação da toolchain antes de release pública |

## Como repetir

1. `npm ci`
2. `npm run typecheck`
3. `npm run lint`
4. `npm test`
5. `npm run test:e2e`

Para evitar alterações de bundles durante os testes de browser, não executar builds da biblioteca em paralelo com o E2E. O build do site gera os downloads em `public/downloads`; os binários não são versionados no Git.

Prioridade de release: implementar ou retirar a designação especializada das visualizações ilustrativas, ampliar a matriz de browsers/acessibilidade, verificar execução Angular num consumidor de produção, atualizar a toolchain e preparar versionamento/publicação npm. Não declarar a biblioteca estável ou universalmente funcional antes desses passos.
